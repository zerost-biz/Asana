# Project Delivery OS（UIプロトタイプ・フル版）

**プロジェクト・作業項目(WBS)・工数・人の負荷・配置・メンバーのスキルと経験** を、ひとつの数字の流れでつなぐ統合管理の、ローカル UI プロトタイプです。
受注前の相談から、プロジェクト化、作業計画、配置、実行、完了、経験の蓄積、次の配置まで、仕様書（`Project_Delivery_OS_FullSpec_Claude_v1.0`）のライフサイクルを一通り触れます。
バックエンド・認証・外部 API なし、`localStorage` に自動保存します（本番は Google Apps Script / Google Sheets に載せ替える想定）。

```
相談・シーズ → PJ候補 → PJ化判断 → 配置の検討 → 実行（作業項目・計画・実績・残り・見込み）
   → 稼働状況／プロジェクトの状態 → 週次レビュー（意思決定）→ 完了 → 経験・スキル → 次の配置
```

> 画面の言葉はすべて日本語です（仕様書の英語名との対応は「[画面の用語と仕様書の対応](#画面の用語と仕様書の対応)」と、画面左下の「用語の説明」）。
> 見た目だけのモックではなく、**入力した内容が全画面に即時反映**されます。

## インストール・起動

Node.js **22.12 以上**を推奨します（起動・ビルドは Node 20 以上で動作。`npm test`（Vitest 5）のみ 22.12 以上）。

```bash
npm install
npm run dev          # http://localhost:5173
```

| コマンド | 内容 |
| --- | --- |
| `npm run build` | 型チェック + 本番ビルド |
| `npm run build:single` | JS/CSS 込みの**単一HTML**（`dist-single/index.html`）。ダブルクリックで開ける |
| `npm run typecheck` / `npm run lint` | 型チェック / ESLint |
| `npm test` | ユニットテスト |
| `npm run e2e` | 画面操作のE2E（p0 / p1 / p2。開発サーバー起動中に実行。Playwright が別途必要: `npm i -D playwright && npx playwright install chromium`） |

> **単一HTML版**はメモリルーター（`VITE_ROUTER=memory`）で動きます。チャットやプレビューの iframe など `localStorage` が使えない環境では、画面上部に「保存されない」旨のバナーが出て、入力はページを閉じるまでの一時的なものになります。

## まず触ってみる（1周の流れ）

右上のユーザーは初期状態で **Kさん（管理者・課長）** です（全機能を操作できます）。ユーザー切替で権限による違いも確認できます。

1. **ホーム**で「要判断」を見る（過負荷・時間超過・遅延・PJ化判断・人員未配置）。赤は重大リスクと100%超の過負荷だけです。
2. **受注見込み** → 案件カードをドラッグ、または段階を選んで動かす → 案件の詳細で必要な役割・工数・スキルを入力 → **PJ化の評価・判断**で8軸を採点して「PJ化する」。
3. **配置**で、案件の役割ごとに候補（適合度つき）を見て、配置前後の負荷を確かめて**仮配置**。稼働状況に「受注見込み分」として載り、100%を超えると警告します。
4. **プロジェクト**の「一覧」で作業項目を編集（作業を追加・マイルストーン・テンプレート・複製・並べ替え・削除）→ **稼働状況**とプロジェクト/ホームの数字が連動して変わる。
5. **自分の作業**で今日の時間・残り・進捗を保存 → 実績↑ → 見込み＝実績＋残り → 差異 → プロジェクト・ホームへ反映。
6. **週次レビュー**で判断し、決定メモを残す。
7. **社内オーダー**: プロジェクトの「社内オーダー」タブでオーダー番号を登録 → 作業ドロワーで作業ごとに計上先を決める → 「自分の作業」で時間を入力するとそのオーダーに計上 → **レポート**で 15日締め／末締めを選んで **CSV** を出力。
8. プロジェクトを**完了処理**すると、メンバーの**経験（候補）**ができる → **メンバー**で確認・確定 → スキルのレベルに反映 → 次の**配置**の推薦に効く。

## 画面の用語と仕様書の対応

| 画面での名前 | 仕様書・開発での名前 | 意味 |
| --- | --- | --- |
| 計画 | PLAN | 最初に見積もった作業時間 |
| 実績 | ACT | これまでに記録された作業時間の合計（`TimeEntry` の合計） |
| 残り | ETC | 完了まで、あと何時間かかるか（担当者が直接入力。進捗の％からは自動計算しない） |
| 見込み（作業・プロジェクト） | EAC | 実績 + 残り（このまま進んだ場合の合計時間） |
| 差異 | Variance | 見込み − 計画（＋は計画より時間がかかる） |
| 工数消化率 | Effort Burn | 実績 ÷ 計画 |
| 標準稼働 / 稼働可能 | Base Capacity / Available | 週の標準時間 / 標準 − 休暇・研修など |
| 確定 | Committed | 決まっている予定（作業の残り＋確定した配置） |
| 受注見込み分 | Expected | 受注前の案件の工数 × 確度 |
| 負荷率 / 受注見込みを含む負荷率 | Utilization / Forecast Utilization | 確定 ÷ 稼働可能 / （確定＋受注見込み分）÷ 稼働可能 |
| 順調 / 注意 / 危険 | GOOD / WATCH / RISK | プロジェクトの状態 |
| 停止中 | Blocked | 進められない作業 |
| 作業項目 / 一覧 | WBS / List | フェーズ → 作業パッケージ → タスク（＋マイルストーン） |
| 受注見込み / 確度 / PJ化 | Pipeline / Probability / 案件→プロジェクト | PJ化前の案件管理 |
| 配置 / 仮配置 / 適合度 | Assignment Planner / Tentative / Match | 人を割り当てる検討 |
| メンバー / スキルマップ | People・Talent / Skill Matrix | 人材基盤 |
| 週次レビュー / 完了処理 | Weekly Review / Project Close | 意思決定 / 完了と経験の記録 |

## 社内オーダーと締めのレポート（CSV）

**社内オーダー** は、プロジェクトごとに登録する「作業時間・人件費の計上先」です（内部オーダー番号）。

- **登録**: プロジェクトの「社内オーダー」タブ（リーダー・課長以上）。番号は **全プロジェクトで重複不可**（全角・小文字は自動で半角・大文字にそろえます）。1つのプロジェクトに複数登録できます。プロジェクトの新規作成時に最初の番号を入れることもできます。
- **作業に設定**: 作業ドロワー（基本）の「社内オーダー」。使用中のオーダーが1つだけのプロジェクトでは、テンプレートで作った作業や作業時間が自動でそのオーダーに計上されます。
- **時間の計上**: 「自分の作業」で時間を入力すると、作業のオーダーに計上されます（入力ごとに選び直せます）。作業時間1件ごとに、計上先オーダーを記録します。
- **終了・削除**: 「終了」にすると新しい入力では選べなくなりますが、過去の集計は残ります。削除すると、使っていた作業・作業時間は「オーダー未設定」に戻ります（作業時間そのものは消えません）。
- **オーダー未設定**: レポートでは「（未設定）」として残り（集計から落としません）、プロジェクトのタブから**まとめて割り当て**できます。

**レポート**（`/reports`・リーダー以上）:

| 項目 | 内容 |
| --- | --- |
| 締め期間 | **前半（15日締め）= 1日〜15日 / 後半（末締め）= 16日〜月末 / 月全体**。◀ ▶ で前後の期間へ動かせます。「今回の締めへ」で今日を含む期間に戻ります。作業時間は **作業日** で期間に振り分けます（両端を含む） |
| 対象 | すべてのプロジェクト、または1つのプロジェクト（`?project=<id>`） |
| 集計 | プロジェクト → 社内オーダーごとの 作業時間(h)・人件費(円)・件数（「担当者別に分ける」も可） |
| 明細 | 作業日・プロジェクト・オーダー・作業番号・作業・担当者・時間・単価・人件費・コメント（1件ずつ） |
| CSV | 「集計をCSVで出力」「明細をCSVで出力」。UTF-8（BOMつき）・CRLF で、Excel でそのまま開けます。「合計行を付ける」で末尾に合計。ファイル名は `社内オーダー別集計_2026年10月前半.csv` のように期間つき。`= + - @` で始まる文字列は式として実行されないよう無害化します |
| 人件費 | 作業時間 × **入力した人の現在の時間単価**（単価の履歴は持ちません） |

実装は `src/domain/closing.ts`（期間）・`orderReport.ts`（集計・CSVの行）・`csv.ts`・`orders.ts`。保存は `src/platform/saveFile.ts`（通常はブラウザのダウンロード。Artifact などプレビュー環境では `downloads` 機能で保存、使えなければ「表示中の表をコピー」で表計算ソフトへ貼り付け）。

## 計算・判定のルール

### 作業時間（P0の核）

| 指標 | 定義 |
| --- | --- |
| 計画（PLAN） | 見積もった作業時間（入力） |
| 実績（ACT） | `TimeEntry.hours` を `wbsId` ごとに合計 |
| 残り（ETC） | 担当者・リーダーが入力する独立値（進捗率から算出しない） |
| 見込み（EAC） | `ACT + ETC` |
| 差異（Variance） | `EAC − PLAN` |
| 工数消化率（Burn） | `ACT / PLAN` |
| 親行 | 計画・実績・残り・見込みは子の合計。進捗は最下位タスクの**計画時間で加重平均**（設定で「見込み時間で加重」に変更可） |
| マイルストーン | 工数 0・進捗の平均に含めない。達成すると「最近の成果」に載る |
| 当初の計画 | 再計画しても、当初の計画時間・開始・終了（ベースライン）を保持して、ドロワーに差分を表示 |

**自分の作業の保存** ＝ 作業時間の記録（TimeEntry）を1件追加 ＋ 残り・進捗・状態を更新。進捗100%は「完了」で**残りは0に強制**、完了を100%未満に戻すと進行中、未着手に時間が入ると進行中、停止中は維持。実装は `src/domain/calculations.ts`（`resolveLogWork`）。

### 人件費と粗利

計画・残りは**担当者**の時間単価、実績は**入力した人**の単価で計算します（担当未設定は平均単価）。粗利 ＝ 受注額 − 見込みの人件費。目安（初期 10%）を下回ると要判断。単価は「管理 → メンバー」で変更（人日単価＝×8h を併記）。

### 稼働状況（Capacity / Workload）

- **確定（Committed）**: 未完了の最下位タスクの「残り」を `max(開始日, 今週の月曜)〜終了日` の平日へ均等配分して週ごとに合算。遅延は今週に全額。WBSを持たないプロジェクトの**確定した配置**も含む。
- **週別の手修正**: ドロワーでその週の時間を直すと、自動配分より優先（「手修正」表示・自動に戻せる）。
- **稼働可能（Available）** ＝ 標準稼働 − 休暇・研修など（週ごとに調整）。
- **受注見込み分（Expected）**: 案件の配置（仮配置）と、未配置の役割需要を **確度** で重み付け。WBSのないプロジェクトの仮配置は ×1。
- **負荷率** ＝ 確定 ÷ 稼働可能。**受注見込みを含む** ＝（確定＋受注見込み分）÷ 稼働可能。85%未満＝通常 / 85〜100%＝注意 / **100%超＝過負荷（赤）**（しきい値は管理で変更）。
- 表示は 4 / 8 / 12 週。「未配置の需要」の行は、誰にも割り当てていない将来の人手（確度加重）。

実装は `src/domain/workload.ts`。

### プロジェクトの状態（自動判定）

| 表示 | 条件（しきい値は管理で変更可） |
| --- | --- |
| 危険 | 見込みが計画を 15% 以上超過、または 遅延と停止中が同時にある |
| 注意 | 見込み超過 5% 以上 / 遅延あり / 停止中あり / 未解決の重大リスクあり |
| 順調 | 上記以外 |

プロジェクトのダッシュボードで手動に切り替えられます。

### 通知・要判断（画面内通知）

過負荷（100%超）・受注見込みを含む過負荷・時間超過・粗利・遅延・停止中（既定1日以上）・リスク・期限が近い作業（既定3日前）・残りの未更新（既定7日）・先行タスクとの日程矛盾・PJ化判断（期限到来）・人員未配置から**毎回導出**します。右上のベルに全件、ホームと週次レビューに「要判断」を出します（`src/domain/alerts.ts`）。

### PJ化の評価（推奨の判断材料）

顧客価値・将来の継続性(LTV)・戦略顧客性・横展開・新しい勝ち筋・組織能力の獲得・人員確保の実現性・リスクの低さを 1〜5 点で採点。入力済みの軸の平均 × 20 が点数（半数以上の入力が必要）。70点以上かつ人員確保が3以上で「PJ化を推奨」、50点以上で「要検討」、それ未満は「見送り寄り」。**自動で可否は決めません**（判断は課長以上）。人員確保の目安は、期間内の空き時間 ÷ 必要工数から提案します。

### 配置の適合度（推薦。最終判断は人）

`スキル適合 40% ＋ 空き適合 30% ＋ 経験適合 15% ＋ 育成適合 10% ＋ 継続性 5%`（重みは管理で変更可）。配置前後の負荷率（受注見込みを含む）を週ごとに表示し、100%を超える週があれば警告します。育成の意図は「理由」として記録できます。実装は `src/domain/talent.ts`。

## データ保存と Reset

- 変更は即座に `localStorage`（キー `project-delivery-os:v3`）へ保存。**社内オーダー導入前の保存データは、捨てずに空のオーダーを補って引き継ぎます**（`migrate`）。リロードしても維持され、別タブの変更は `storage` イベントで同期します。表示設定（金額/時間・週数など）は `project-delivery-os:pref:*`。
- 更新履歴（監査ログ）は直近 500 件を保持し、「管理 → 更新履歴」とドロワー/概要に表示します。
- データ構造を変えたらキーのバージョンを上げると、古い保存データは破棄して seed から再開します（v2 → v3 でフル版の項目を追加したため、以前のデータは初期化されます）。
- **Reset**: 右上の ⚙ →「デモデータを初期化」、または「管理 → データ」。保存データを消して今週基準の seed に戻します。「管理 → データ」では JSON の書き出しもできます。

## 自分のGoogleで試す（トライアル）

`gas/` に、Google Apps Script + スプレッドシートで動かすための一式があります（`Code.gs` / `index.html` / `appsscript.json`）。手順は **[gas/README.md](gas/README.md)**。Apps Script 上で開くと自動で `GasRepository`（スプレッドシート保存）に切り替わり、レポートのCSVはGoogleドライブに保存されます。自分1人用のトライアルで、複数人の同時編集・本物の権限確認は含みません。

## 将来 GAS（Google Apps Script + Google Sheets）へ移植する際のポイント

**そのまま持っていけるもの**: `src/domain/*`（DOM・React 非依存の純粋な TypeScript）。UI は Vite でビルドした成果物を GAS の HTML Service に載せる想定です（`build:single` で単一HTML化）。

**差し替えるもの**

| 現在（プロトタイプ） | 本番（GAS + Sheets） |
| --- | --- |
| `repository/LocalStorageRepository.ts` | `GasRepository`（`google.script.run` 経由で Sheets を読み書き）。`Repository` インターフェース（`load / save / clear / subscribe`）は共通 |
| `store/AppContext.tsx` の保存（全体保存） | 起動時に一括ロード、更新は差分保存（`saveWbs` / `appendTimeEntry` …）＋楽観的更新・失敗時ロールバック |
| `data/seed.ts` | 初期データ投入の `setupSheets()` |
| `AppData.currentUserId` / 画面側の権限 | `Session.getActiveUser().getEmail()` と Users の突合。**権限はサーバー側でも必ず検証**（UI非表示だけに頼らない） |
| `BrowserRouter` | GAS の iframe では履歴 API が使えないため `HashRouter` かメモリルーター（`VITE_ROUTER=memory`） |
| `storage` イベント同期 | ポーリング、または更新時の再取得 |
| 画面内の通知 | 必要に応じて Gmail / Chat 通知を追加（`alerts.ts` の結果を送る） |

**シート設計の目安**（1テーブル＝1シート、1行＝1レコード。ID は固定の接頭辞付きID、日付は `yyyy-MM-dd`）

`Users` / `Skills` / `UserSkills` / `GrowthFocus` / `Customers` / `Opportunities`（＋ `OpportunityDemands` `OpportunitySkills`）/ `Projects`（＋ `RoleNeeds`）/ `InternalOrders`（番号は一意）/ `WBS`（`orderId`）/ `TimeEntries`（追記専用・`orderId`）/ `Assignments` / `AllocationOverrides` / `Capacities` / `Risks` / `Experiences` / `ProjectCloses`（＋ `CloseMembers`）/ `ActivityLog` / `ReviewNotes` / `Settings`。

**設計上の注意**

- ACT は `TimeEntries` の集計で導出し、WBS に保存しない。人件費・親行の集計・Workload・Health・通知も保存せず毎回導出する（現在の方針のまま）。
- 同時編集は `LockService` で保護し、`updatedAt` / 版番号で競合を検知する。
- `google.script.run` は遅いので「起動時に一括取得 → メモリ上で計算 → 保存は debounce」にする。
- 単価の履歴が必要になったら `Rates`（userId, 適用開始日, 単価）を追加して TimeEntry の日付で引く。

## 仮定と未実装（プロトタイプの範囲）

- 実装しない: 本格的な GAS / Google Sheets 連携（トライアル版は `gas/`）、本物の認証、メール・チャット通知、外部API、会計・請求・外注費などの本格的な原価管理、AI機能。
- 権限は画面側のロール切替（ログインなし）。ユーザーの追加は管理でできるが、削除はなし（「停止」にする）。
- タイムラインはバーのドラッグ編集なし（日付はドロワーで変更）。依存関係は矢印の簡易表示。
- 稼働は週次のみ・祝日は考慮しない（平日＝稼働日）。ETC の配分は均等配分の近似（週別に手修正可）。
- 受注見込みの週別需要は、期間内の稼働週へ均等配分（役割ごとの工数）。複数案の What-if は「案の比較」（候補2〜3名の比較表）までで、保存はしない。
- 単価は「現在の単価」で全期間を再計算（履歴なし）。更新履歴は直近500件。
- 社内オーダーに予算（時間・金額）や、締め後の入力ロック（締め済みの期間の変更禁止）はありません。締めの区分は 15日・末日の固定です。
- 検索はプロジェクト・作業・案件・メンバー名の部分一致のみ。
- 作業名の一部（As-Is整理・To-Be設計）は、仕様書の受入基準に合わせた名称です。
